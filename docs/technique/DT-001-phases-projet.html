1. Besoin

Dans un bureau d'études, un projet passe par des phases successives :

  1. Préliminaire — diagnostic de l'existant, relevés…
  2. APS — avant-projet sommaire
  3. APD — avant-projet détaillé
  4. DAO — dossier d'appel d'offres
  5. Contrôle et surveillance des travaux

Les sous-tâches traitées dépendent de la phase : certains types de tâche n'existent que dans une phase (un relevé en Préliminaire), d'autres servent dans plusieurs (une note de calcul en APS et en APD). À la création d'une sous-tâche, la liste des types doit cadrer les équipes sur la phase en cours, tout en restant flexible pour deux exceptions courantes :

  • pendant l'APD, une correction d'un livrable d'APS ;
  • pendant l'APS, un travail en avance sur l'APD.

Le statut du projet (la demande racine) n'était pas exploité : il devient le porteur de la phase en cours.

2. Principes retenus

Décision (option B, « flexible à long terme »). Un type de tâche peut appartenir à plusieurs phases, et chaque tâche enregistre sa phase. L'option A (un type, une phase, phase de la tâche déduite du type) obligeait à dupliquer les types communs (« Note de calcul APS », « Note de calcul APD ») et ne savait pas classer une correction d'APS faite pendant l'APD.
PrincipeConséquence
La phase en cours se lit sur le statut du projet Pas de champ en double : le flux de travail du type « Projet » (Préliminaire → APS → APD → DAO → Contrôle) donne l'ordre des phases, et ses transitions autorisent les retours en arrière.
Lien explicite phase ↔ statut Aucune reconnaissance par le libellé : renommer un statut, changer de langue ou de domaine ne casse rien.
Un statut désigne une seule phase La phase en cours est toujours unique. Une phase peut avoir plusieurs statuts (un par flux de travail).
Portée : phase d'un espace ou commune Les mêmes phases (APS, APD…) se définissent une fois pour tous les espaces de travail ; un espace peut ajouter les siennes. Même logique que la portée des champs personnalisés.
La phase d'une tâche est fixée à la création et gardée Une correction d'APS faite pendant l'APD reste comptée en APS, dans le Gantt comme dans les rapports.
Proposer, ne pas interdire La liste des types montre d'office la phase en cours ; les autres phases restent accessibles d'un clic.

4. Phase courante d'un projet

La phase courante est celle liée au statut de la demande racine, parmi les phases visibles dans son espace (les siennes et les communes), dans l'ordre du projet. Une tâche de n'importe quel niveau lit le statut de sa racine.

Sans phase en cours, rien n'est caché : toutes les entrées sont proposées à la création d'une sous-tâche. Avec une phase en cours, seuls les types rattachés à cette phase sont proposés d'office ; ceux des autres phases et les types sans phase restent accessibles par « autres phases » (correctif du 20/10/2026, 2.0.30).

5.1 À la création

5.2 Ensuite

  • Modification de la tâche (formulaires) : la phase n'est pas lue, elle est conservée.
  • Correction : setIssuePhase classe la tâche dans une autre phase de son type. Un type à phases exige une phase ; un type sans phase n'en accepte aucune.
  • Changement de type : la tâche garde sa phase si le nouveau type l'utilise, sinon la règle 5.1 s'applique.
  • Phases d'un type modifiées : les tâches existantes gardent leur phase (historique).
  • Phase supprimée : ses types et ses tâches sont conservés, sans cette phase.

6. Création d'une sous-tâche

La requête typesSousTacheParPhase(parentIssueId) renvoie une entrée par couple (type, phase) : un type utilisé dans deux phases donne deux entrées. Choisir une entrée fixe le type et la phase.

11. Paramétrage pas à pas (bureau d'études)

  1. Dans le flux de travail du type « Projet », créer les statuts Préliminaire, APS, APD, DAO, Contrôle (et Suspendu, Clôturé) et leurs transitions, retours compris.
  2. Écran Phases : créer les phases dans l'ordre, cochées « Commune » si tous les espaces les partagent.
  3. Pour chaque phase, lier le statut du projet correspondant (« + statut… »).
  4. Pour chaque sous-type, choisir ses phases (Relevé : Préliminaire ; Note de calcul : APS et APD ; Réunion : aucune).
  5. Faire avancer un projet en changeant son statut : la création de sous-tâches suit.

13. Limites et évolutions

  • Les phases communes sont ordonnées globalement : les réordonner depuis un espace change leur ordre partout.
  • Rendre commune une phase dont le nom existe dans un autre espace est refusé (pas de fusion automatique).
  • Les rapports par phase (avancement, temps passé par phase) peuvent s'appuyer directement sur issue.phase_id.
  • Autre source de phase courante : implémenter ResolveurPhaseCourante.
