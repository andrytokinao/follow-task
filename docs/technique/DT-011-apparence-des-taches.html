DT-011

Icône et couleur du type, couleur du statut sur toutes les tâches

Une tâche se reconnaît partout à l'icône de son type, dans la couleur du type, et à la couleur de son statut.

RéférenceDT-011 (Document Technique n° 011)
StatutRéalisé
Version de l'application2.0.21
Date19 octobre 2026
Commits liéstitres contenant « (DT-011) » : git log --grep "DT-011"

1. Besoin

L'icône et la couleur choisies pour un type (DT-010) et la couleur d'un statut n'apparaissaient presque nulle part : icônes non teintées, icônes codées en dur (dossier, fiche, fa-tasks), couleurs devinées d'après le nom (« bug », « story », « done »…). Surtout, les requêtes ne demandaient pas issueType.color, ni la couleur des statuts d'un flux.

2. Comportement

TOPO-12 Levé du terrainEn cours
TOPO-13 Reprise des cotesTerminé
  • Icône du type dans la couleur du type ; nom du type en info-bulle.
  • Type sans icône : dossier pour une demande (niveau PARENT), fiche pour une tâche. Sans couleur : gris.
  • Statut : pastille dans sa couleur ; colonnes de board, onglets et menu de statut teintés.
  • Écrans concernés : liste des tâches, tableaux et boards, sous-tâches, détail, fil d'Ariane, sélecteur de tâche, liens, messagerie, événements, documents, notifications, calendrier, création et changement de type, écrans Direction (accueil, fiche projet, tâches, Gantt), séances du planning (DayPilot).

3. Architecture du code

FichierRôle
common/type-tache/type-tache.util.tsRègle unique : iconeDuType, couleurDuType, couleurDuStatut, replis
common/type-tache/*<app-type-tache [type]> : icône teintée
common/statut-tache/*<app-statut-tache [status]> : pastille en lecture seule (pour changer le statut : app-status-field)
type/graphql.operations.ts, issue-link.operations.ts, phase.operations.ts issueType { level color icone { id value typeIcone } }, status { color }, statuses { color } ajoutés là où ils manquaient
common/icone-viewInchangé, reçoit [color] ; console.log retiré

Les composants sont autonomes (standalone), importés dans les modules qui importaient déjà IconeViewComponent. common.module utilise CUSTOM_ELEMENTS_SCHEMA : un composant non importé ne casse pas la compilation, il ne s'affiche simplement pas.

4. Limites

  • Planning (DayPilot) : le HTML des séances est construit dans events.service.ts (iconeTache) avec les mêmes règles, pas avec le composant.
  • Direction, liste des projets : seuls les projets ont une icône ; la situation du jour (DT-005) a son propre modèle.
